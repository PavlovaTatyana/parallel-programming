# Лабораторные работы по параллельному программированию

**Выполнила:** Павлова Татьяна, группа 6214-100503D

---
## Постановка задачи
Написать программу на C++ для перемножения двух квадратных матриц.
- Матрицы читаются из файлов
- Результат сохраняется в файл
- Замеряется время и объём задачи
- Верификация через Python + NumPy

## Реализация
- **Язык:** C++ 
- **Умножение:** тройной цикл с порядком `i-k-j` для лучшей работы с кэшем (последовательный доступ к памяти).
- **Замер времени:** `std::chrono::high_resolution_clock` (замеряется только само умножение, без учета генерации и записи файлов).
- **Оптимизация I/O:** Запись матриц в файлы выполняется только при `N <= 200`, чтобы дисковые операции не искажали результаты замеров на больших размерах.
- **Верификация:** Python + NumPy (сравнение с эталонным результатом).

## Выводы

1. **Сложность O(N³)** — время растёт кубически с размером матрицы.
2. **Малые N** (200, 400) — очень быстро (меньше секунды), матрицы помещаются в кэш.
3. **Большие N** (1600, 2000) — время растёт быстрее теоретического O(N³) из-за промахов кэша.
4. **Верификация через NumPy** — максимальная ошибка ~10⁻¹⁵, что соответствует машинной точности `double`.
5. **Экспериментальные точки** - общая тенденция  теоритической и экспериментальной кривых совпадает.

# Лабораторная работа №2: OpenMP умножение матриц

## Постановка задачи
Модифицировать программу из ЛР №1 для параллельной работы по технологии OpenMP.
Провести эксперименты с разным количеством потоков (1, 2, 4, 8) и разными размерами матриц (200, 400, 800, 1200, 1600).

## Реализация

- **Язык:** C++.
- **Технология:** OpenMP (директива `#pragma omp parallel for`).
- **Параллелизация:** внешний цикл  распараллелен по строкам матрицы `i`. 
- **Замер времени:** `omp_get_wtime()` (замеряется только само умножение).
- **Верификация:** Python + NumPy.

## Выводы

1. **Эффективность OpenMP**: наибольшее ускорение достигнуто на больших матрицах (N = 1200 и N = 1600), где время выполнения удалось сократить в 5.5–6 раз при использовании 8 потоков.

2. **На малых размерах матриц** (N = 200, 400) параллельная версия работает нестабильно. Это объясняется тем, что время, затрачиваемое на создание потоков и их синхронизацию, превышает время самих вычислений. Параллелизм эффективен только при достаточном объеме вычислений.

3. **Закон Амдала**: С ростом числа потоков (с 4 до 8) эффективность падает. 

4. **Верификация**: Результаты параллельной программы были успешно сверены с эталонным вычислением через NumPy. Погрешность не превышает машинной точности double.
